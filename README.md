# 隨時資料庫

上課、聽 Podcast 時產生的照片、錄音、筆記,一鍵丟進 Google Drive 自動歸檔、自動命名、自動寫進索引表,之後找得回來。

個人自用的小工具,不是通用產品——公開出來單純因為 GitHub Pages 免費方案只能架在公開的 repo 上。

## 它解決什麼

上課拍的白板照片散在相簿裡、錄音檔叫「新錄音 47」、筆記記在隨便一個 App 裡,過兩週就再也找不到是哪一堂課的東西。這個工具把入口統一成「先選課程,再拍照/錄音/記筆記」,後端自動把檔案歸到 `隨時資料庫/(分類)/課程/年/月/類型/` 底下,並在一張 Google Sheet 索引表登記,App 裡可以直接瀏覽或跨課程搜尋。

## 功能

- **拍照上傳** — 選好課程直接拍,自動歸檔;離線時進佇列,連上網自動補傳
- **錄音歸檔** — 手機語音備忘錄分享到 Drive 收件夾,後端每 5 分鐘自動掃描歸檔(不限檔案大小)
- **課堂筆記** — App 內建編輯器(章節、螢光筆、粗斜體、字體顏色),存成原生 Google 文件,同一天同一課程會更新同一份
- **Podcast 歸檔** — 貼 Apple Podcasts 集數連結,背景自動下載音檔存進課程資料夾,可以離開頁面
- **課程分類** — 課程可歸到「學習 / 工作 / 投資 / 家庭」底下,也可以維持未分類
- **全域搜尋** — 不用先選課程,直接關鍵字搜所有課程的檔名/標題
- **自動對帳** — 直接在 Drive 增刪檔案後,App 會自動把索引表對齊實際內容

## 架構

```
apps-script/    後端(Google Apps Script):Web API、收件夾掃描、歸檔、對帳、Podcast 背景下載
pwa/            前端(單一 HTML 檔的 PWA):拍照、筆記、搜尋、離線佇列
docs/           安裝與使用說明
tests/          後端邏輯的回歸測試
```

技術上刻意維持精簡:**沒有建置步驟、沒有相依套件、沒有 CDN**。前端就是一個自足的 `index.html`(手刻 Range API 做富文字編輯,沒有引入編輯器函式庫),後端就是一份可以直接貼進 Apps Script 編輯器的 `Code.gs`,測試只用 Node 內建模組。

- 前端推到 `main` 後由 GitHub Actions 自動部署到 GitHub Pages
- **後端不會自動部署**,`Code.gs` 改完要手動貼回 Apps Script 編輯器並重新部署新版本

## 測試

```bash
node --test
```

零相依,不用先 `npm install`。測試用 Node 內建的 `vm` 把真正的 `apps-script/Code.gs` 載進沙箱,只把 Apps Script 專屬服務換成替身——測到的是實際會部署上去的那份程式碼,不是另外抄一份邏輯。推送時 CI 也會跑同一份測試。

涵蓋範圍集中在「壞掉不會有徵兆」的地方:Podcast 分段下載的截斷偵測、分類資料夾的走訪與存在性判斷、全域搜尋的比對與排序。前端 `index.html` 的 UI 邏輯沒有納入自動測試,改動時仍以瀏覽器實測為主。
